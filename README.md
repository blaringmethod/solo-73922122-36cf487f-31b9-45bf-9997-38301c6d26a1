# 国土调查地类拆分核算 API

国土调查更换地类图例后，统计员需要估计：旧图中某旧地类的像元，有多少能算入指定的新地类，
以便决定哪些图幅还需外业复核。本服务登记旧图幅各地类像元数、外业补报的新地类整幅总数
（手工补报与外业分块复核两种来源）、新旧地类对照表（一个旧码可对应多个新码），并对任意
「图幅 + 一对新旧地类」给出**重合像元数的最小值与最大值**；两值相同即为确数。

## 数学模型

每个图幅独立构成一个运输型拆分问题：

- 变量 `x[旧码][新码] ≥ 0`（整数），仅当对照表允许该对时存在；
- 行约束：每个旧地类的像元必须全部分配出去（= 旧图登记数）；
- 列约束：每个已复核新地类的列和必须恰好等于有效复核总数；
- 未复核新地类列和不限，吸收剩余像元。

约束矩阵全幺模，用**最小费用流**（`app/solver.py`，纯 Python 实现，无外部求解器依赖）直接
得到整数最优解。已复核列用**带下界的汇边**（下界=上界=复核数）精确锁定：经典超级源/汇
补流判定下界可行性，再在纯业务残余图上推满流；优化阶段用 Bellman-Ford 负环消除求查询
变量的最小/最大值，固定边残余容量为 0，列和在整个优化中始终锁定。所有前向费用非负（0/1），
算法必然终止。

## 外业分块复核规则

外业把一幅图划分为若干互不重叠、覆盖整幅的分块，分块上报各新地类的像元数：

- **登记一次**：`PUT /sheets/{id}/blocks` 登记该图幅的分块编号清单，重复登记返回 409；
- **按块提交、整份替换**：`PUT /sheets/{id}/blocks/{bid}/counts` 提交该块各新地类的
  非负整数像元数，重传即整份替换该块报表（服务端只存各块报表，合计按需重新推导，
  更新一块无需回读其他块）；
- **齐报才采用合计**：某新地类在**每个**分块都报了数（**填 0 也算已报**）才视为齐报，
  采用各块之和作为该新地类的整幅合计；任一块漏报即不齐，不产生合计；
- **重传漏项撤下、手工沿用**：重传后某新地类不再齐报的，撤下其分块合计；若该新地类
  另有手工复核数，则沿用手工数；
- **手工与合计并存须相等、只计一次**：同一新地类手工数与齐报合计并存时必须相等，
  有效复核数只计一次；不相等即冲突，引发冲突的整次更新回滚。

图幅查询（`GET /sheets/{id}`）与 `/overlap` 使用**同一已提交状态下推导的有效复核数**。

## 一致性设计

- 所有更新（登记计数、手工补报/更正、分块登记、分块报表重传、整表换对照表）都在
  `BEGIN IMMEDIATE` 事务内**先写入、再校验受影响图幅**（手工/分块冲突 + 可行性）：
  只要造成复核数冲突或有图幅无解，整次更新回滚，返回 409 并列出受影响图幅及原因；
  因此已提交状态恒可行，原报表与生效数据保持不变；
- 换表校验以**提交那一刻**已提交的计数为准；复核登记接口始终可用，换表核对期间照常登记；
- 查询只读已提交状态：单连接 + 全局读写锁，读写互斥，一次查询看到同一已提交快照。

## API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/legend` | 查看当前对照表（含版本号） |
| PUT | `/legend` | 整表更换对照表，体为 `{"mapping": {旧码: [新码...]}}` |
| PUT | `/sheets/{id}/old-counts` | 登记/替换图幅旧地类像元数，体为 `{"counts": {旧码: 像元数}}` |
| PUT | `/sheets/{id}/review-totals` | 手工补报/更正图幅新地类复核总数，体为 `{"totals": {新码: 总数}}` |
| PUT | `/sheets/{id}/blocks` | 按图幅登记一次外业分块编号清单，体为 `{"blocks": [块编号...]}` |
| GET | `/sheets/{id}/blocks` | 查看分块清单、各块报表、齐报状态与有效复核数 |
| PUT | `/sheets/{id}/blocks/{bid}/counts` | 按块提交/重传新地类像元数（整份替换，填 0 算已报） |
| GET | `/sheets` | 列出已有数据的图幅及像元合计（含分块数） |
| GET | `/sheets/{id}` | 查看某图幅已登记计数、手工数、分块报表与有效复核数 |
| GET | `/overlap?sheet_id=&old_code=&new_code=` | 查询重合像元数 min/max，`exact=true` 时 `value` 为确数 |

计数均为非负整数（负数返回 422）；手工计数 0 等价于不登记，分块计数 0 保留并视为已报。
不在对照表中的新旧地类对，重合像元数恒为 0（`in_legend=false`）。

## 运行

### Docker Compose（推荐）

```bash
docker compose up --build
```

服务监听 `http://localhost:8000`，Swagger UI 在 `http://localhost:8000/docs`，
SQLite 数据落在名为 `land-data` 的卷中（容器内 `/data/land.db`）。

### 本地运行

```bash
pip install -r requirements.txt
uvicorn app.main:app --port 8000          # 数据库默认 ./data/land.db，可用 LAND_DB_PATH 覆盖
```

### 测试与演示

```bash
python3 -m pytest tests/ -q               # 38 个单元/端到端测试
bash scripts/demo.sh                      # 对 localhost:8000 走一遍完整流程（含分块齐报与重传漏项）
```

`scripts/demo.sh` 演示：登记对照表与两幅旧图 → 手工补报复核数与更正 → 分块清单登记
（重复登记被拒）→ 单块上报不生效、齐报后合计生效 → 图幅查询与 /overlap 同口径 →
重传漏项撤下合计 → 手工数与合计冲突被 409 拒绝 → 换表前后对比 → 非法换表/非法复核被拒且原数据不变。
